# Orchestra 1.x RC performance baseline

The 1.x RC keeps the existing turn-economy and Direct Work probes as the release performance contract rather than introducing a new benchmark with different semantics.

Representative scenarios covered by the release gate:

- routine/mechanical work stays on the mechanical/direct path without unnecessary delegation;
- implementation packets remain bounded and delta-oriented;
- retries remain bounded and preserve prior valid work;
- review/escalation paths remain policy-driven rather than unconditional;
- Work Lease checks add factual authority fencing without transcript migration;
- self-contained runtime install/Doctor checks execute locally without provider/model calls.

The authoritative executable probes are:

- `tests/direct-work/turn-economy-probes.test.mjs`
- `tests/turn-economy/instrumentation.test.mjs`
- `tests/turn-economy/token-semantics.test.mjs`
- `tests/turn-economy/fidelity.test.mjs`
- `tests/turn-economy/turn-diet.test.mjs`
- `tests/turn-economy/critical-review-consensus.test.mjs`

These tests are included in the full `npm test` RC gate. A release candidate is not considered technically ready if these executable performance/turn-economy contracts regress, even when functional tests pass.
