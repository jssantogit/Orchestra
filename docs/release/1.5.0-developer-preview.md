# Orchestra 1.5.0 — developer-preview operational guide

> This document describes the **Draft PR implementation**, not the currently released V1.4.3. Do not install 1.5.0 into canonical production worktrees while CI or native field validation is pending.

## Temporary linked worktrees

Use the main checkout only as an anchor for Git; all Codex runtime files and Work Leases live under the new worktree. Supply the real source checkout and an empty destination.

```powershell
$cli = 'C:\Projects\Orchestra\scripts\orchestra-worktree.mjs'
$repo = 'C:\Projects\Tsuzuki'
$wt = 'C:\Projects\Tsuzuki-F6C-lab'
$sha = '<approved-full-commit-sha>'
node $cli create --repo $repo --path $wt --branch exp/f6c-lab --from $sha
node $cli list --repo $repo
node $cli doctor --path $wt
node $cli uninstall --path $wt --dry-run
node $cli uninstall --path $wt
```

These commands are synchronous, on-demand and do not launch a persistent Orchestra daemon. A failed installation preserves the worktree for inspection rather than deleting it. The worktree-specific `uninstall` accepts only linked Git worktrees (not the original checkout), removes both Orchestra runtimes after safe preflight, and **never deletes the worktree, its branch or product files**. For a non-worktree project, use the separate generic runtime uninstall command deliberately.

## Codex linked-worktree hook discovery incompatibility (upstream #27133)

Native Tsuzuki F6D and issue #154 field reports confirmed that Codex 0.159.2 /
0.164.0 use the *primary checkout* for project-hook discovery in linked Git
worktrees, even when the linked checkout's project `.codex/config.toml` is
effective. Installing Orchestra's `.codex/hooks.json` only in that linked
worktree consequently yields zero native Orchestra hooks when the primary
checkout has none. This happens **before** hook trust, execution or response
protocol. Never copy project hooks automatically to the main checkout: those
hooks would execute with another checkout's authority and code.

An explicit alternative for Codex-native field testing is an **independent
local clone**. It has its own Git metadata and project-root hooks while leaving
the primary checkout and all other worktrees untouched:

```powershell
$cli = 'C:\\Projects\\Orchestra\\scripts\\orchestra-worktree.mjs'
$repo = 'C:\\Projects\\Tsuzuki'
$isolated = 'C:\\Projects\\Tsuzuki-codex-isolated'
$sha = '<approved-commit-sha>'
node $cli create-clone --repo $repo --path $isolated --branch exp/native-hooks --from $sha
node $cli doctor --path $isolated
# After the user explicitly trusts the project, review hook definitions in /hooks.
# Test a *real* SessionStart/CONTROL before claiming that native hooks work.
```

This opt-in command invokes `git clone --no-local --no-checkout`, checks out
the pinned commit on a new branch, installs the candidate locally and runs
Doctor. It does not share worktree Git administration, copy trust, change user
global config, or automatically open/approve Codex hooks. The clone is preserved
on failures, never reset/deleted automatically. It is **not** part of the parent
repository's `git worktree list`. To remove just the runtime later, after all
Codex sessions/tools have ended, use the generic official
`orchestra-codex-project.mjs uninstall <isolated> --dry-run --json` then
`uninstall <isolated> --json`. Do not call the linked-worktree-specific
`orchestra-worktree.mjs uninstall` for independent clones.

The source-level Doctor retains `healthy= true` only for byte integrity and
separately shows `hookActivation.checkoutType`,
`discoveryCompatibility = KNOWN_UPSTREAM_HOOK_ROOT_REDIRECT` on linked
worktrees with local hooks, and `localHookDiscovery = NOT_VERIFIED`.
This is a **version-sensitive compatibility diagnosis**, never proof of a
specific CLI process's activation/trust. For independent clones the current
discovery status remains UNVERIFIED pending actual native `/hooks` observation.
No automatic trust, primary-hook install or global workaround is supported.

The existing Git `info/exclude` patterns now cover the verified managed
`.orchestra/runtime/delegation/**` payload in addition to state, without
hiding unrelated `.orchestra/user...` data. An already-installed older
runtime should not be modified while it has an active session.

## Official reversible uninstall

```powershell
$manager = 'C:\Projects\Orchestra\scripts\orchestra-codex-project.mjs'
node $manager uninstall $wt --dry-run --json
node $manager uninstall $wt --json
```

Only byte-verifiable manifest-owned files are removed. Both Codex and neutral delegation runtimes are inspected before any removal. Work Lease writer, unrecognized ownership, drift, or non-quiescent runtime prevents an uninstall. `.orchestra/state`, evidence, rollback backups, and product code survive. `git worktree remove` is a completely separate operation and is never automatic.

The shared Git `info/exclude` block intentionally remains: linked worktrees may still rely on its stable managed-state patterns. It is not truly per-worktree Git metadata.

## Chat blocked by an old Work Lease

Version 1.5 lets a fresh factual Codex session **continue submitting text prompts** even if the Work Lease is occupied or stale. This is not mutation authority: `PreToolUse` still rejects unauthorized tools.

To inspect without changing the lease:

```powershell
$recover = 'C:\Projects\Orchestra\scripts\orchestra-recover.mjs'
node $recover inspect --repo-root $wt
```

`WRITER_LIVENESS_UNKNOWN` is deliberately *not* proof that an old process exited. First explicitly close the former Codex session and verify there are no in-flight tools. An operator may then authorize a bounded terminalization at the exact current lease generation:

```powershell
node $recover abandon --repo-root $wt --expected-generation 0 --confirm-old-session-closed
```

Only use `--preserve-dirty` when the operator has inspected and explicitly approved preserving uncommitted changes. The CLI never discards dirty product files, never kills processes and never changes Git branches. It appends a small operator receipt in the local state and marks the old lease `BLOCKED` with no mutation capabilities. The next newly started Codex session claims a newer Work Lease generation. Do **not** use this command while the old session/tool can still mutate the checkout; already-running tools cannot be cancelled retroactively.

Run `inspect` again if the worktree has changed or the expected generation is stale. No automatic recovery is attempted on `UNKNOWN` liveness.

## Field-test discovery and trust prerequisite (F6D finding)

The first practical F6D field run installed a valid 1.5-candidate image, but
Codex 0.159.2 did not load the project-local Orchestra hooks. `Doctor: HEALTHY`
therefore certifies only file/manifest integrity. The Doctor and worktree Doctor
now report `hookActivation.status = UNVERIFIED` until a real native session is
verified separately. Do not claim SessionStart or Work Lease authority from a
healthy byte installation alone.

Codex requires two independent operator-controlled trust steps:

1. The project-local `.codex/` configuration layer must be trusted.
2. The exact non-managed hook definitions must be reviewed and trusted through
   the Codex CLI `/hooks` browser (changed definitions need fresh review).

In the actual worktree, first inspect its project trust configuration and then
use interactive Codex `/hooks`. If only plugin hooks are visible, treat project
hook discovery as **not established**; do not classify it as a protocol error
without additional evidence. Do **not** edit user-global hook config, auto-trust,
or bypass Codex security policy.

After the operator explicitly trusts the project and hooks, start a fresh
native Codex session and prove a real SessionStart/CONTROL Work Lease. Only then
test a protected tool and its PostToolUse release. Noninteractive `codex exec`
cannot silently supply the user's interactive approval; keep the fallback to
native Codex if activation is unavailable.

The Orchestra 1.5 prerelease package and manifests report `1.5.0-rc.1`. The
source Git commit must still be pinned and recorded independently. This
identifier does not mean the official stable 1.5.0 has been published.

## Native Codex hooks

V1.5 projects SessionStart and PreToolUse responses to Codex 0.159's closed wire schema. Semantic PreToolUse denials exit successfully with a native deny, and a session bound before a runtime image/manifest change is rejected as `SESSION_RUNTIME_STALE`. Launch a fresh factual Codex session after a runtime upgrade.

## Release gate

Still required before promotion: exact-HEAD CI, an actual Codex-native integration smoke in real development ("teste à vera" means practical validation, **not** a particular computer), complete recovery regression review, and final operator approval. No baseline memory/latency/token/turn-economy benchmark against plain Codex is a release gate for 1.5.0: this release makes bounded lifecycle and safety fixes rather than importing V2's heavy control plane. Functional checks should still catch unexpected resident services, background workers or extra LLM calls. Investigate performance only if a real regression appears. V2 remains isolated beta work.
