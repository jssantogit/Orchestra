# Orchestra 1.x RC architecture

This document is the release-candidate delta for the existing architecture/provider guides. It is normative for the 1.0 RC where older 0.x examples conflict with it.

## Canonical ownership

- `core/**` is provider-neutral policy, authority, evidence, acceptance, Work Lease, and schema runtime logic.
- `providers/<provider>/**` owns provider-specific catalogs, adapters, and thin project-runtime wrappers. Providers depend on core; core never depends on a provider; providers never depend on each other.
- `runtime/manifests/*.json` owns distribution composition. Runtime builds consume canonical core/provider/Lab sources and emit self-contained provider images.
- `runtime/project-runtime-manager.mjs` owns manifest-driven install/update/backup/rollback semantics and preserved project-state handling.
- `labs/**` owns experimental/advisory components. Dream and Jev have explicit authority `NONE`.
- `runtimes/**` remains the provider compatibility/install surface; generated/provider-installed paths are not canonical policy ownership.

The provider wrappers in `providers/codex/project-runtime-manager.mjs` and `providers/antigravity/project-runtime-manager.mjs` delegate to the shared manager and bind only provider identity/manifest selection. Runtime-local managers under `runtimes/**` remain compatibility surfaces for already-installed self-contained CLIs; source installers must not depend on them.

## Runtime distribution

Codex and Antigravity distributions are built from manifests. Installed runtimes include canonical core schemas and provider adapters and must execute without imports from the Orchestra checkout or its `node_modules`.

Project updates replace only manifest-managed runtime roots. Neutral `.orchestra/state/**` and declared provider telemetry/artifact/semantic/runtime-management state are preserved and hidden locally via the bounded Orchestra block in `.git/info/exclude`; tracked product `.gitignore` is not mutated.

Rollback backup identifiers are bounded to a single runtime backup directory; traversal/absolute backup identifiers fail closed. Runtime builds likewise reject output directories that contain the Orchestra checkout, preventing destructive recursive cleanup of the source tree.

## Authority

Model identity is never authority. Provider session/conversation identity is provenance. Work Lease generation fences workspace mutation. Acceptance remains control-plane-only and candidate/evidence-bound. Narrative handoff/context cannot grant capability, lease, evidence, scope expansion, or acceptance.

Dream and Jev are zero-authority Labs. Lab output may inform observation/analysis, but cannot accept work, grant capabilities, claim Work Leases, mutate product state, or self-promote into authoritative evidence.

Dream is canonically sourced from `labs/dream/runtime` and packaged into the compatible installed `.agents/dream` destination. Jev is canonically available from `labs/jev`; legacy runtime/experiment locations remain compatibility or regression surfaces only.

## Health and release

`npm run doctor` is manifest/schema/invariant driven. It validates manifest shape, package/manifest version coherence, manifest-owned assets/entrypoints, deterministic builder behavior, contamination/firewall boundaries, and self-contained installed-runtime smoke behavior.

The RC version is `1.0.0-rc.0`. Technical readiness is checked by `npm run release:readiness` plus the clean CI RC gate. Stable `1.0.0`, tags, GitHub Releases, repository governance changes, merges, and downstream synchronization remain operator-gated Task 9 actions.

Rollback levers remain available during the RC window:

- `ORCHESTRA_DIRECT_WORK_MODE=off|shadow|on`
- `ORCHESTRA_AUTHORITY_MODE=session|dual|lease`

See `docs/migrations/0.10-to-1.x.md` and `docs/release/1.x-checklist.md` for migration and release operations.
