# Orchestra 1.x release checklist

This checklist separates technical release readiness from operator-authorized external mutations.

## RC technical gate

- [ ] Schema validators regenerated and `check:schemas` clean.
- [ ] Runtime images regenerated and `check:runtimes` clean.
- [ ] Runtime manifests complete and version-coherent.
- [ ] Shared manifest project manager install/update/dry-run/rollback contract green.
- [ ] Installed Codex and Antigravity runtimes pass self-contained smoke tests without source-checkout imports.
- [ ] Dream and Jev Labs declare `authority = NONE` and authority tests are green.
- [ ] Manifest-driven Doctor reports healthy.
- [ ] Cross-runtime contamination and firewall checks are green.
- [ ] Direct Work and Work Lease suites are green.
- [ ] Full `npm test` regression is green.
- [ ] RC release-readiness check is green.
- [ ] Independent whole-branch review/security review has no unresolved blocker.

## Rollback readiness

- Direct Work lever documented: `ORCHESTRA_DIRECT_WORK_MODE=off|shadow|on`.
- Authority lever documented: `ORCHESTRA_AUTHORITY_MODE=session|dual|lease`.
- Runtime update/rollback preserves declared project state and user `.git/info/exclude` entries.
- Stale lease generations remain fail-closed.

## Task 9 — operator approval required

Do **not** perform any item below as part of technical Phase 5 completion:

- bump stable version to `1.0.0`;
- create or push a stable tag;
- publish a GitHub Release;
- change branch protection/rulesets/required checks;
- merge the diagnostic/stacked Phase 5 PR;
- delete release branches;
- synchronize Orchestra into Tsuzuki or another downstream project.

These actions require an explicit operator release decision after the RC technical gate is green.
