# Orchestra 1.0.1 Doctor & Windows Hotfix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the official Codex project lifecycle and Doctor share the v2 runtime contract, and make release verification portable across Windows and Linux.

**Architecture:** Keep `.orchestra/state/runtimes/codex.json` as the single canonical Codex installation metadata. Route source-level Codex project commands through the manifest-driven provider manager and compare projects against freshly built runtime payloads. Make build metadata OS-independent while preserving executable-bit checks only where the platform exposes POSIX mode semantics.

**Tech Stack:** Node.js 20, node:test, GitHub Actions.

**Spec:** Runtime behavior observed from the first Orchestra v1.0.0 installation into Tsuzuki and the v1.0.0 release contracts.

## Global Constraints

- Do not modify or retag `v1.0.0`.
- Canonical metadata remains `.orchestra/state/runtimes/codex.json` with schema `orchestra.project-runtime.v2`.
- Do not recreate `.codex/orchestra-runtime.json`.
- Preserve fail-closed integrity checks, rollback integrity, and project-owned state.
- Validate Windows and Linux.
- Prepare version `1.0.1` only after behavior is green.

## Review Focus

- Fresh install followed immediately by Doctor.
- Existing v1.0.0 install updated without legacy metadata adoption.
- Runtime drift still fails Doctor.
- Runtime build metadata is deterministic across Windows/Linux.
- Existing rollback and project-state preservation remain intact.
