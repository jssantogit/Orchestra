# Orchestra 0.10 → 1.x migration

Orchestra 1.x keeps migration reversible until stable release authorization. Upgrade runtime images through the manifest-driven project manager and keep project state outside tracked product files.

## Direct Work rollback

`ORCHESTRA_DIRECT_WORK_MODE=off|shadow|on`

- `off` restores the pre-Direct-Work path.
- `shadow` evaluates Direct Work without granting it mutation/acceptance authority.
- `on` enables Direct Work under the current capability, lease, evidence, and acceptance contracts.

If Direct Work behavior regresses, move `on → shadow → off`; do not bypass Work Lease or acceptance rules to preserve the feature.

## Authority rollback

`ORCHESTRA_AUTHORITY_MODE=session|dual|lease`

- `session` uses legacy session authority.
- `dual` evaluates session + Work Lease compatibility while preserving fail-closed behavior.
- `lease` makes the Work Lease the mutation authority.

Rollback `lease → dual → session` only as an explicit migration action. Stale lease generations never regain mutation authority.

## Runtime update and rollback

Provider runtime installs/updates are manifest-driven. Managed runtime files may be replaced, but preserved state stays outside those managed roots. Updates create a rollback backup before destructive replacement; rollback restores managed runtime bytes while preserving project-owned state and `.git/info/exclude` user entries.

State that must remain preserved includes neutral `.orchestra/state/**` plus provider runtime state, telemetry, artifacts, semantic state, and runtime-management histories declared by the runtime manifest.

## Labs

Dream and Jev are Labs with `authority = NONE`. Their output is advisory. Migration must not turn Lab observations into capability grants, Work Lease claims, product mutations, evidence promotion, or acceptance decisions.

## Release boundary

`1.0.0-rc.0` may be used for repository-local release-readiness verification. Stable `1.0.0`, tags, GitHub release publication, protection/ruleset changes, and downstream project synchronization require an explicit operator release decision.
